# 本机通达信低负载运行方案

当前网页是 GitHub Pages 静态站点。它不能访问你电脑上的通达信、SQLite 或
`localhost`，因此“通达信已登录”不会自动让公网页面出现数据。页面只有在
`/daily-data/latest.json` 和 `reports/index.json` 被发布后才会显示行情。

## 当前状态

- 仓库已有统计和页面，但没有常驻采集器，也没有真实的 `daily-data` 文件。
- `collector.probe_tdx` 使用通达信安装目录自带的只读 TQ 接口，不接交易接口。
- 探测器不会启动第二个通达信实例，也不会保存账号密码。
- 通达信未启动或未登录时，接口会初始化失败；这不是网页故障。

## 推荐运行方式

1. 交易日打开通达信并登录，保持客户端运行；锁屏可以测试，休眠会停止采样。
2. 先做单股连接检查：

   ```text
   py -m collector.probe_tdx --code 000001.SZ
   ```

3. 连接成功后再做一次短基准测试，确认全市场读取耗时和覆盖率：

   ```text
   py -m collector.probe_tdx --benchmark 600
   ```

4. 采集器只在交易时段每 60 秒读取一次快照，内存只保留五分钟窗口；午间和
   收盘各生成一次报告。不要每分钟提交 Git 或重建整个网站。
5. 报告文件通过外部 HTTPS 只读存储发布到 `daily-data`。电脑离线时网页保留
   最近一次成功报告，并显示过期状态。

## 负载控制

- 复用已经打开的通达信，不启动浏览器自动化、Docker 或第二个数据库服务。
- 先用 `--benchmark 600` 测量，再决定是否读取全市场；若单次读取超过目标，
  降低采样频率或改用合规的外部行情源。
- 首次历史资料补全和新闻解释任务在盘后运行，并可暂停，不阻塞行情采样。
- 只读接口与交易下单完全分离；不要把账号密码、API Key 或原始数据库上传到
  GitHub。
